# 5 分钟展示讲稿与操作卡

按老师转录安排：5 分钟展示（含功能演示），约 5 分钟提问。若学院新通知不同，以新通知为准。主汇报 8 页；A1—A4 为备用答疑，不逐页读。

时间分配：20＋25＋35＋30＋30＋30＋90＋40 秒＝300 秒。除演示外约 210 秒；先按此稿熟悉，再以实际彩排计时调整。备注中的来源与补充说明不用照读。

## 第 01 页 · 让网络故障诊断有事实、有过程、有验证

【20 秒】各位老师好，我们的项目是 NetPath-Doctor。长期目标是让程序操纵网络模拟环境，从设备反馈中提取信息并定位故障。本阶段先在 eNSP 三路由器网络上建立可解释、可重复验证的诊断原型。正式项目名称与编号按立项书填写。

## 第 02 页 · 先在一套真实运行的拓扑里闭环

【25 秒】R1 和 R2 通过 10.0.12.0 网段互联，R2 和 R3 通过 10.0.23.0 网段互联，目标是 R3 的环回地址。两种故障都在 R2 注入：关闭出接口或删除目标静态路由。本轮通过本机 Console 获取 VRP 回显，SSH 放到下一阶段。图是结构示意，实景截图由现场采集补充。来源：docs/ensp/address-plan.md、scenarios/live/*.example.json。

## 第 03 页 · Agent 根据反馈选择下一条检查命令

【35 秒】状态机先产生动作，映射为命令，LiveExecutor 调用 Console 传输层读取设备输出。Parser 把文本转成 facts，状态机再决定下一步。这构成观察、决策和执行的循环。当前策略是人写的规则，不是大模型。外层控制器负责实验注入和恢复，避免把诊断与配置修改混在一起。来源：agent/state_machine.py、tool_server/live_executor.py、benchmarks/live_experiment.py。

## 第 04 页 · 先读懂设备文字，再判断故障

【30 秒】以接口为例，Parser 从 current state 和 Line protocol 两行提取物理和协议状态，将 Administratively Down 归一成 DOWN。这页文本是结构示意，不是新实验截图。空回显不能直接证明故障，例如无路由需要回退完整表并验证条目完整性。字段来源：parser/huawei_vrp.py。两类受控实验允许使用已采集的故障前路由基线继续检查出接口，这是受控实验的前提。

## 第 05 页 · 两条诊断路径，输出可核对的证据

【30 秒】ping 失败后定位疑似设备，再查目标路由。当前路由缺失时，如果有本轮故障前的出接口记录，就继续读接口：物理 DOWN 返回 INTERFACE_DOWN，UP/UP 返回 ROUTE_MISSING，解析失败或协议单独 DOWN 则请求更多数据。两类实验都提供同样的基线，不传预期故障标签。结果保留命令轨迹和证据。来源：DiagnosisStateMachine.run。

## 第 06 页 · 离线回归和真实报告已经归档

【30 秒】113 项测试和 4 个子测试通过，离线 Benchmark 为 20/20。20 个案例由 6 个独立 CLI 基线和 14 个参数化变体组成，不代表 20 次现场实验。材料还保留 eNSP Console 两类各 3/3 的历史报告，以及 Qwen/百炼只读诊断报告。旧版曾出现一次接口端点误判为 R3，这个报告被保留为问题发现证据，后续代码已用 administrative_down 和端点优先级修复。中期以这些报告、日志和代码测试为主要证据，现场即时复测属于后续强化。来源：evidence.json、reports/live/、reports/ai_trace/、benchmarks/README.md。

## 第 07 页 · 展示报告：从设备反馈到诊断结论

【90 秒，含展示】先展示一份已保存的 eNSP 或 Qwen/百炼报告，沿 action_trace 指出诊断命令、设备、故障类型、required_evidence 和恢复检查。报告中的原文、JSON 和代码版本可以现场打开核对。若后续准备了录像，明确标注录制时间和版本；本次中期不要求即时启动 eNSP。来源：reports/live/、reports/ai_trace/、docs/ensp/实验复现步骤_中文.md。

## 第 08 页 · 中期收口：补证据、稳演示，再扩大范围

【40 秒】段振阳负责材料整合、讲解和彩排；李梦瑶负责拓扑与 eNSP 证据；邓予钦负责 Parser、原文校验和回归。PPT 大纲、讲稿、技术报告、历史 eNSP 报告和 Qwen/百炼报告已经形成中期证据链。后续再推进 SSH、多模拟器、更多故障和模型对照。我们的中期成果是一个有设备反馈、有结构化事实、有可核对结果的诊断原型。谢谢老师。

## 开始前操作卡

确认拓扑已启动、无其他实验正在运行；预先打开本轮 JSON 和原文目录，准备演示命令，不现场敲长命令。故障实验结束后必须确认恢复；需要手工处置时先停止演示并保留错误记录。单次全流程超过 90 秒，改展示只读诊断与已保存的完整报告，录像作为明确标注的备份。

## 提问时的查找顺序

代码问题看 A1 和《代码导读与答疑》；能力边界看 A2；Agent、Benchmark 和恢复机制看 A3；来源和版本看 A4 与 evidence.json。未知问题如实说尚未验证，并给出计划验证的方法。
