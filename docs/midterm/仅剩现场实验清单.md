# 下一次开 eNSP 时的清单

本阶段非现场准备已完成：PPT 大纲、讲稿、报告技术正文、代码导读、采集校验工具。剩余现场工作按下面顺序串行进行。最终 PPT 排版按组长安排后续制作；正式登记信息和签字另行核对。

## 1. 李梦瑶：接口原文采集

在业务网络正常时，在 R2 执行 `display interface GigabitEthernet0/0/1`，把完整命令与回显保存为 `docs/cli_records/normal/interface_detail_R2.txt`（UTF-8）。

进入 system-view 和该接口，执行 shutdown 后 return，再执行同一条详细查询，保存为 `docs/cli_records/interface_down/interface_detail_R2_down.txt`。最后进入同一接口 undo shutdown，return 后查询，保存为 `docs/cli_records/recovered/interface_detail_R2_recovered.txt`。

恢复后 R1 ping 192.168.3.1 确认连通；不保存 shutdown 状态到启动配置。这一轮人工采集与自动实验分开进行，不在自动脚本运行时同时操作 CLI。

每份文件另在 `docs/cli_records/README.md` 记录采集人、时间、eNSP/VRP 版本、设备、命令、状态。保留正文，分页必须读完；若用程序捕获，说明首尾提示符已被传输层移除。不要把构造文本或之前的简表改名冒充详细原文。

## 2. 邓予钦：原文直接校验

工具已经写好，不需要先改 Parser 才能检查：

```powershell
.\.venv\Scripts\python.exe tools/check_midterm_interfaces.py --output reports/live/console_interface_capture_check.json
```

退出码 0 代表三个文件均能解析、接口名正确、正常/关闭/恢复分别 UP-UP、DOWN-DOWN、UP-UP；2 表示尚缺文件；1 表示有文件但内容未通过。当前缺文件时返回 2 是如实报告待采集，不能称为三个测试通过。

校验只证明格式与预期状态一致，文件真实来源须人工复核。若真实 VRP 的状态与预期不同，保存原文、排查原因，禁止直接改回显。报告与源码一起保留即可；现有 tests 可继续跑，不需要重复拷贝原文到多个目录才能验收。

## 3. 段振阳：最终版本的两类 3 次实验

按 `docs/ensp/实验复现步骤_中文.md`，先 preflight，再依次执行两类故障，每类 --trials 3。所有命令显式带 `--transport ensp-console`，避免使用默认 SSH。

报告同时检查：故障前正常、注入成功、diagnosis_status=COMPLETED、设备 R2、故障类型正确、接口正确（接口案例）或目标网络正确（路由案例）、恢复成功、恢复后的 packet_loss。不要只看 all_passed；出现 FAIL 时保留日志，先恢复网络再继续。

特别检查接口关闭造成路由撤销的情况。已修正为先依据故障前出接口记录检查当前接口；若仍给出 ROUTE_MISSING，不能记为 INTERFACE_DOWN 通过。保存原文排查；离线完成不保证现场一定无需修复。

## 4. 段振阳：录制与回填

记录 `git rev-parse HEAD`、`git status --short`、实验时间；保证 JSON、原文目录和录像来自同一运行。只需录制一条最稳定的完整流程，另一类可现场展示对应报告。

PPT 大纲第 6 页保留历史结果，将“当前版本：待复测”替换成真实新结果与运行编号。报告第 3.3 节填入实际通过数和丢包率。若要刷新文件哈希，另存一份最终实验清单，不覆盖旧证据的含义。

现场演示时间预算约 90 秒。先在本机测单次流程实际耗时；超过预算时，现场展示已启动程序的一次只读诊断，并展示保存的完整实验报告。完整过程录像作为备份，按规定允许的时间播放，注明录制日期和版本，不能假称为现场即时运行。

## 5. 彩排

最终 PPT 制作后，在实际演示电脑检查放映、字体、音视频和离线备份；全流程讲解＋演示控制在 5 分钟内。之后互问代码与证据问题，准备约 5 分钟提问。若学院发布新的时间安排，以其为准。
