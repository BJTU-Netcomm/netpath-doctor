## 段振阳 集成实验与主讲

1. 在集成机启动最终拓扑，核对三台 Console 端口、正常 ping 及 R2 静态路由。
2. 按中文复现步骤串行运行两类故障，各 3 次；不得同时手工修改 CLI。
3. 核对每轮故障类型、设备、接口或目标网络、恢复结果及丢包率。接口关闭却诊断成路由缺失不能算通过。
4. 保存同一版本、运行编号的 JSON、原文、时间和 git commit；录制至少一条完整流程。
5. 将实际结果填入技术报告第 3.3 节和 PPT 大纲第 6—7 页；学习已有讲稿及代码导读。
6. 最终 PPT 制作后完成计时彩排：约 210 秒讲解＋90 秒演示。软件兼容和投影以实际电脑验证。
7. 对照立项书核对正式名称、编号、导师和经费；办理学校模板、教师审核、签字及系统提交。

交付：两类各 3 次报告及原文、录像、回填后的报告与大纲。验收：诊断均正确，恢复成功，恢复后可达且逐次记载 packet_loss；不把历史报告当作本轮实验。

## 邓予钦 原文解析与回归验收

1. 三态文件到位后运行 `python tools/check_midterm_interfaces.py --output reports/live/console_interface_capture_check.json`。
2. 核对 interface、physical_status、protocol_status；退出码 0 为通过，2 为缺文件，1 为未通过。缺文件不得记作通过。
3. 直接使用 `docs/cli_records/` 原文作为 fixture，补充真实三态回归并记录来源。无需再复制出一套相同原文目录。
4. 如果真实格式未被解析，保留原文后修正 Parser 并重跑；保持 V1 字段及字符串 required_evidence，不擅自升级契约。
5. 运行 pytest 与离线 Benchmark，记录 commit、测试摘要及是否有回归。
6. 复核已有代码导读的调用链，准备 Parser 和状态机技术答疑；构造回归不能描述为现场实测。

交付：三态解析检查 JSON、真实回显回归测试、`docs/ensp/parser-interface-validation.md`、测试与版本记录。验收：三态正确解析，回归全部通过，Benchmark 20/20。
