# 中期答辩任务书

版本：2026-10

本阶段目标是形成一套可以现场演示、可以复核、可以解释的 eNSP 故障诊断原型。

本阶段暂不安排 SSH 自动控制开发。SSH、更多故障类型和大模型接入列入下一阶段。

## 任务一：组长 / 集成与答辩负责人

### 负责内容

1. 使用集成实验机启动 R1、R2、R3，并确认拓扑正常。
2. 运行 `INTERFACE_DOWN` 和 `ROUTE_MISSING` 两类真实实验。
3. 每类故障连续运行 3 次。
4. 保存每次实验的 JSON 报告、原始 CLI 回显和运行时间。
5. 检查每次实验是否满足：
   - 故障前网络可达；
   - Agent 输出正确故障类型和设备；
   - 故障恢复成功；
   - 恢复后网络重新可达。
6. 维护 `feat/midterm-integration` 分支，合并经过检查的队友提交。
7. 负责 PPT 最终排版、汇报顺序和现场演示。
8. 完成 5 分钟讲稿，并准备现场操作失败时的离线演示备份。

### 交付物

```text
reports/live/                 6 次现场实验报告
reports/live/*_raw/           对应的原始回显
docs/ensp/topology.md         最终拓扑说明
答辩PPT                         最终版
答辩讲稿                        5 分钟版本
演示录像                        至少 1 次完整流程
```

### 验收标准

```text
INTERFACE_DOWN：3/3 通过
ROUTE_MISSING：3/3 通过
每轮 recovery.success = true
每轮恢复后 reachable = true
JSON、原始回显和录像可以按编号对应
PPT 可以在没有现场修改代码的情况下完成演示
```

## 任务二：李梦瑶 / eNSP 现场证据负责人

### 负责内容

1. 在 R2 上采集详细接口命令的正常状态：

   ```text
   display interface GigabitEthernet0/0/1
   ```

2. 执行 `shutdown` 后再次采集同一命令。
3. 执行 `undo shutdown` 后采集恢复状态。
4. 每份文件保留设备提示符、输入命令、完整回显和采集状态。
5. 删除密码、账号和无关个人信息，不修改命令输出正文。
6. 补充接口关闭故障的注入命令、恢复命令和预期现象。
7. 核对拓扑、接口、IP 地址和故障命令与 `docs/ensp/` 中的说明一致。
8. 为 PPT 提供三张材料：拓扑截图、接口正常截图、接口关闭截图。
9. 撰写 PPT 中“真实实验环境与故障注入过程”部分的文字初稿。

### 交付物

```text
docs/cli_records/normal/interface_detail_R2.txt
docs/cli_records/interface_down/interface_detail_R2_down.txt
docs/cli_records/recovered/interface_detail_R2_recovered.txt
docs/ensp/interface-fault-record.md
拓扑截图、接口状态截图
PPT“实验环境与故障注入”页面初稿
```

### 验收标准

```text
三份文件均为 display interface 的详细回显
正常状态能看到 UP/UP
关闭状态能看到接口或协议 DOWN
恢复状态重新回到 UP/UP
三份文件来自同一套 R1-R2-R3 拓扑
没有密码和无法解释的手工改写
```

## 任务三：邓予钦 / Parser 与技术讲解负责人

### 负责内容

1. 接收李梦瑶提供的三份详细接口原始回显。
2. 将三份回显加入 `scenarios/real_outputs/interface/`，保留来源说明。
3. 在 `tests/` 中增加正常、接口关闭、恢复三种状态的 Parser 测试。
4. 验证以下字段：

   ```text
   physical_status
   protocol_status
   interface
   ```

5. 运行全部测试和离线 Benchmark，记录最终结果。
6. 检查测试是否误把 `display ip interface brief` 当成详细接口回显。
7. 撰写 PPT 中“Agent、Parser 和规则状态机如何工作”部分的技术初稿。
8. 准备 3 分钟代码原理讲解：输入、解析、事实、规则决策、诊断输出。
9. 列出当前系统限制：规则状态机、离线 Benchmark、现场拓扑范围和未接入 SSH。

### 交付物

```text
scenarios/real_outputs/interface/*
tests/test_real_vrp_outputs.py 的接口测试
docs/ensp/parser-interface-validation.md
pytest 与 Benchmark 结果记录
PPT“系统原理与代码流程”页面初稿
3 分钟技术讲解稿
```

### 验收标准

```text
正常、关闭、恢复三种真实回显都有测试
physical_status 和 protocol_status 解析正确
pytest 全部通过
Benchmark 20/20 通过
测试不会把构造样例冒充真实采集
技术讲解能说明 Agent 当前是规则状态机，不是大模型
```

## PPT 和讲稿的固定分工

组长负责把三人的初稿合成最终版本；每个人只负责自己的页面和讲稿段落。

```text
组长：项目目标、整体架构、实验结果、结论、现场演示
李梦瑶：eNSP 环境、拓扑、故障注入、真实设备截图
邓予钦：Parser、规则状态机、测试方法、当前限制
```

## 本阶段明确不做的内容

```text
SSH 自动控制设备
大模型 API 接入
自动启动 eNSP GUI
新增大量故障类型
把离线 Benchmark 结果说成现场实验结果
```

这些内容放入答辩最后的“下一阶段计划”，不影响本阶段先完成可复核的两类故障闭环。
